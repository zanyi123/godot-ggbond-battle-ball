# 31 · 召唤体身份地基与操控通道统一工单（快捷开发系统前置）

> **来源**：主人三连问（2026-10-06）——"水鲨鱼分不清敌我/为什么判定逻辑会有问题/是不是修复了还只能这两个队用（这是要做到快捷开发系统的）"。
> **回答（先行）**：根因=**召唤体身份链断裂**（非操控体系问题）：技能施放路径调 `spawn(type_id, caster_id, pos)` 不传 params → 实体 owner_ref=null → 敌我识别兜底成"a"队 → **水木（B队）鲨鱼追杀自己队友、伤害归因 attacker=null**。操控窗/引导/接触伤害全踩在空身份上——这就是多轮返工的共同根源。
> **通用性回答**：修复后**不是**只有两队可用——身份/敌我/伤害/操控全部由数据声明驱动（types json：kind/controllable/contact_damage；技能：tags+operator），任何新队伍**零新代码**（02表 11~16 行的甲虫/蒙面侠/飞狐等未来操控技同款接入）。

## 一、根因链（取证）

| 层 | 问题 | 后果 |
|---|---|---|
| 生成路径 | `_apply_summon_spawn` → `sm.spawn(三参)` 无 params；仅自动生成路径带身份 | 实体 owner_ref=null |
| 敌我识别 | 实体 my_team 兜底 `"a"` | B队鲨鱼 hunt 自己队友 |
| 伤害归因 | attacker=null | take_damage 归因失败 |
| 操控归属 | player.summons 登记/窗判定依赖身份 | 引导链抖动 |

## 二、修复（已实施）

1. **身份单点解析**（summon_manager）：`_resolve_owner_node(owner_id)`（battle 名册权威+存活实体借用兜底）；`spawn()` 对空 owner_ref **统一注入**——施放/自动生成/融合/未来路径一处覆盖
2. **实体队伍解析链**（summon_entity）：`_resolve_my_team()` = owner_ref.team → mgr._team_of → **空=fail-closed 不猜队**（接触命中/爆炸均挂此链，身份不齐不伤害）
3. 验证：r14 套件 **38/38**（B队身份/咬敌/不咬队友/施放路径无 params 原形）+ 回归 6 套件绿 + 平台端到端零报错

## 四、快捷开发系统契约（新队接入姿势）

```
新队伍操控技 = skills.json 声明（operator=OP_STEER/OP_MARK + tags 含 summon_spawn）
            + summon_types.json 声明（kind/controllable/contact_damage/lifespan/burrow）
→ 自动获得：单击即施放 / 操控窗随召唤体 / 鼠标引导(steer) / 点击锁定(mark) /
  敌我识别与伤害归因随施法者 / 全灭收窗恢复行走 —— 零新代码
```
