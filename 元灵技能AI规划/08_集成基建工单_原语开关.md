## 一、设计：两层开关 + 单口拦截（复用项目成熟先例）

| 层 | 载体 | 语义 |
|---|---|---|
| 全局总开关 | `master_enabled` | false=原语系统**整体旁路**（查表永远未命中→走旧三大类评分分支），行为=现状 |
| 分波开关 | `waves.{A/B/C/D/E}` | master=true 时，仅标记为 true 的波参与查表；false 的波其描述符**视为不存在**（同样走 fallback） |

**先例依据**：`operator_system_enabled`（操2大点1.5）=单口拦截、关闭全旁路、不改任何函数签名；`USE_3D_SCENE`=sim 强制降级。本开关完全同构。

**单口位置**：`primitive_registry.gd` 的查询层（`get_descriptor`）——**spirit_ai_manager 完全不知道开关存在**（接线代码零条件分支，开关语义全部收口在 registry）。manager 侧无感知 = 主游戏路径不受污染。

**fail-closed 三条**：switches.json 缺失/损坏/字段非法 → 一律视同**全关**；未知波次字母 → 视同关；开关读取异常 → 视同关。**宁可不启用，不可误启用。**

## 五、测试矩阵（test_spirit_ai_switches.gd 断言组）

| 组 | 断言 |

## 六、每波对接的标准启用流程（写入集成窗口 SOP）

```
波X集成接线完成（manager 查表路径接通）
  → 全关状态跑一遍：全量回归 + sim 与 baseline 逐位一致（接线本身零扰动证明）
  → switches.json 开波X（master=true, waves.X=true）
  → 波X套件全绿 + 全量回归全绿 + sim 危险=0（此时行为允许变化，diff 逐条归因记入看板）
  → 观察期（主人实机或 sim 多跑）无异常 → 该波保持开启
  → 任何异常 → 该波开关即回 false（秒级止血，无需回滚代码）→ 看板"问题"列登记
```

**开关即止血阀**：出问题关开关，不动代码、不动基线——这是渐进启用的核心收益。
