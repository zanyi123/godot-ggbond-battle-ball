## 一、总架构：原语如何插进现有决策管线

```
现状管线（spirit_ai_manager，集成窗口的接线目标，增益窗口只读）：
  _decide_skill(sad)
    → _get_available_skills（能量/冷却/失误短冷却过滤）      ← 不动
    → _compute_skill_score = base_value × 10因子             ← base_value 换原语表驱动
    → Softmax → 阈值 → _execute_skill                        ← 不动

原语层插入点（两个）：
  ① 价值计算：base_value 由"子类描述符表"逐标签算（替换 33/103 覆盖的旧分支，
     旧分支保留为兜底 fallback——表里查不到的 tag 走原逻辑，行为零破坏）
  ② 时机闸门：候选技能放分前先过 timing_gate（gate 不过=本周期跳过，无惩罚），
     gate 通过给 bonus ∈ [0.5, 2.0] 乘进分数
```

**多标签技能规则**（复用现有权重）：逐标签 value × 权重（1标签1.0 / 2标签各0.7 / 3标签各0.5）求和；时机闸门 **OR 逻辑**——任一标签 gate 通过即放行，bonus 取通过者最大值。全确定性，无随机。

## 二、JSON 契约：`data/systems/spirit_ai/primitives_a.json`

### 2.1 Schema（字段冻结）

```json
{
  "schema_version": 1,
  "wave": "A",
  "updated": "2026-09-25",
  "descriptors": {
    "<tag_id>": {
      "family": "ball_stat | player_attr | energy_mgmt",
      "direction": "self | enemy",
      "timing_gate": "<gate键，见§三>",
      "value_param": "<tag_params 里的参数名，如 value/multiplier/duration>",
      "value_unit": <float，每单位参数的价值分>,
      "value_min": <float，默认15.0（对齐现有兜底分）>,
      "value_cap": <float，上限≤90>,
      "intent": "attack | defense | support | control",
      "intent_strength": <float 0~1>,
      "target_mode": "ball | self | enemy_visible | ally_support | none",
      "notes": "<一句话，可空>"
    }
  }
}
```

### 2.2 字段约束（增益窗口自检清单）

| 字段 | 类型 | 约束 | 违反后果 |
|---|---|---|---|
| tag_id | string | **必须与 tags_registry.json 的 id 逐字一致**，39个一个不缺 | 套件断言失败 |
| family | 枚举 | 三选一 | 套件断言失败 |
| direction | 枚举 | self=给自己/自己球；enemy=给敌人 | 同上 |
| timing_gate | 枚举 | 必须是 §三 定义的 gate 键 | 同上 |
| value_param | string | **以 registry 该标签的 params 数组为准核对**（ball数值族多为 value/multiplier；player 族核对 value/duration） | 运行时取 0 分 |
| value_unit/value_min/value_cap | float | value_min ≤ value_cap；全表 value_cap ≤ 90 | 同上 |
| intent/intent_strength | 枚举+float | 与 direction 语义一致（给敌的 debuff → control/attack） | 评分失真 |
| target_mode | 枚举 | enemy_visible 走 02 工单的 FOV 闸门（fail-closed） | 越界选中=回滚 |
| **禁新增字段** | — | 需要新字段 → 看板"问题"列申请，规划窗口批 | 回滚 |

## 三、时机闸门键（冻结，全 12 个；各波共用）

| gate 键 | 判定条件（ctx 由 manager 组装，见 §四） |
|---|---|
| `always` | 恒真，bonus=1.0 |
| `ball_hold` | p.is_carrying_ball |
| `ball_hold_engage` | is_carrying_ball 且视野内有敌（FOV 闸门） |
| `enemy_visible` | 视野内（FOV）存在敌人 |
| `enemy_carrying_visible` | 敌持球者存在且在其 FOV 内 |
| `self_threatened` | 视野内敌距离 < ctx.threat_radius（默认 200px）或 stamina_ratio < 0.4 |
| `self_injured` | stamina_ratio < 阈值（默认 0.35） |
| `ally_injured` | 支援目标评分最低的队友 stamina_ratio < 0.35 |
| `calm_state` | 非持球 且 视野内无敌 且 stamina_ratio > 0.5 |
| `pre_burst` | 自己最高 base_value 的技能当前被能量/冷却卡住（资源时机） |
| `ball_flight` | 球在飞行中（本波不用，预留给操球窗口） |
| `ally_cast_setup` | 收到 COMBO_SETUP 消息窗口内（本波不用，预留给⑤协议） |

**bonus 规则**：gate 通过 → bonus=1.0（基础）；条件处于"强触发"（如 self_threatened 且敌距离<100px）→ 1.25；实现只需两档，禁更细（防调参爆炸）。

## 四、GDScript 契约：`scripts/battle/spirit_ai/primitives_a.gd`

### 4.1 文件骨架与函数签名（冻结）

```gdscript
class_name SpiritAIPrimitivesA
extends RefCounted
## 波A原语：纯增益/资源族（39标签）。契约见 元灵技能AI规划/06_原语接口规约.md
## 纪律：禁 randf/instance_id/直连 ai_manager 感知数据（感知走 ctx）；缩进 Tab

const TABLE_PATH := "res://data/systems/spirit_ai/primitives_a.json"

## 读表（进程内缓存一次；JSON 解析失败返回 {} 并 push_error，绝不崩溃）
static func get_descriptors() -> Dictionary

## 时机闸门。descriptor 里取 timing_gate 分发；ctx 由 manager 组装：
## ctx = {
##   "player": CharacterBody2D,          # 施法者
##   "fov_ap": Dictionary,                # 02工单感知口 get_ap_for_player 结果（可能为空=fail-closed）
##   "visible_enemies": Array,            # FOV 内敌人引用列表（manager 算好，原语不算感知）
##   "stamina_ratio": float,
##   "energy_ratio": float,
##   "has_energy_blocked_burst": bool,    # pre_burst 用：manager 判断好
##   "threat_radius": float,              # 默认 200.0
## }
## 返回 {"ok": bool, "bonus": float}；未知 gate 键 → {"ok": false, "bonus": 1.0}（fail-closed）
static func timing_gate(descriptor: Dictionary, sad: Dictionary, ctx: Dictionary) -> Dictionary

## 价值计算：value = clamp(params[value_param] × value_unit, value_min, value_cap)
## params 缺该键 → 返回 value_min（不猜参数名）
static func compute_value(descriptor: Dictionary, tag_params: Dictionary) -> float

## 本波无动态目标逻辑，target_mode 静态读表（预留动态化签名，后续波覆写）
static func resolve_target_mode(descriptor: Dictionary, sad: Dictionary) -> String
```

### 4.2 编码纪律（增益窗口红线）

1. **禁 `randf()`/`randi()`/`randf_range`**——需要随机处一律 `sad` 上已有的确定性骰子范式（02 工单A），本波预计用不到
2. **禁读 `ai_manager.ai_players` 原始数据**——感知信息只从 `ctx` 取（01 #1 感知收口的延伸纪律）
3. **禁碰白名单外文件**（05 §一）：本波只写 `primitives_a.json` / `primitives_a.gd` / `test_spirit_ai_wave_a.gd` + 看板自己行
4. 缩进 Tab；注释风格照 spirit_ai_manager 现有中文注释
