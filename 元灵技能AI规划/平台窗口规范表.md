# 平台窗口规范表 —— AI-Full 平台测试全流程

> 性质：**平台窗口作业规范**（非工单，无编号、不销项）——凡在 AI-Full 平台测试技能/AI/参数，窗口照此执行，主人照此验收。
> 生效：主人 2026-10-01 令"全流程梳理，给窗口也给主人"。修订须主人认可。

---

## 一、流程总览（六步）

| 步 | 名称 | 执行者 | 要点 |
|---|---|---|---|
| 1 | 配置 | 平台窗口 | 测试三件套就绪（见 §二） |
| 2 | AI 通道 | 平台窗口 | headless 批量跑，探针自动判定 |
| 3 | 玩家通道 | 主人 | 按原作说明实机操作，探针判定效果 |
| 4 | 门禁 | 平台窗口 | 模拟健康红线核验 |
| 5 | 问题处置 | 窗口 / 归属窗口 / 主人 | 三级分流（见 §四） |
| 6 | 交付 | 平台窗口 | 标准五件套（见 §五） |

## 二、配置三件套（测试前必须就绪）

1. **装载同步**：本轮被测技能/队伍写入当前主装载——**先同步主装载，再跑测试，再汇报**（主人面板所见与窗口实测必须是同一套）。
   - 历史场景装载文件留存互不覆盖；场景切换在主装载文件内完成或跑批时显式指定。
2. **元灵挂接**：平台测试用元灵走内存注册，**零污染主数据**；命名规约=原作球员的元灵 / 队伍元灵。
3. **开关姿势声明**：
   - 机制扩展批新技能在交付关断态下 **AI 不会使用**（无旧计价惯性）——需要观察 AI 使用，临时开启对应开关（**谁开谁登记，测完字节级还原**）；
   - 每份测试报告**必须注明开关态**（关=验证"不使用"侧，开=验证"会使用"侧，两态都是验收的一部分）。

## 三、两条通道

### AI 通道（窗口跑批）
- headless 自动跑，多种子起步（默认 3 种子）；
- 探针自动判定：每技出手数、效果落地事件、协同信号、僵死检测、场终判定（VERDICT）；
- 单技通过标准：**出手 >0 且效果落地**，且跨种子非孤例。

### 玩家通道（主人参与）
- 入口：编辑器打开平台场景 → F6 → 排表面板确认（面板显示的装载=窗口实测的同一套）；
- 主人操控选项为**学打法专用次要开关**（默认不勾，平时全自动）；
- 通过标准：**按原作说明操作 = 原作描述的效果**；
- 探针全程记录（操作序列/事件计数），主人只管玩，判定自动出。

## 四、问题处置（三级分流）

| 级别 | 判定 | 处置 |
|---|---|---|
| **本级可修** | 平台白名单文件 / 数据配置 / 明显参数缺键 | 自修 → 复测 → 闭环（报告注明"已修"） |
| **跨域上报** | 他人归属域（管理器/计价/描述符/操控域等）或他人未提交文件 | **不碰**，收集归轨：问题清单标注归属窗口，进看板/决策文件 |
| **需主人拍板** | 数值定版 / 口径 / 排期 / 开关还原确认 / 批量新增数据 | 进决策文件待定夺区，注明提出窗口，等裁决 |

## 五、交付五件套（每轮测试的固定收尾）

1. **验收矩阵**（每技：出手数/效果落地/判定，一眼全貌）；
2. **看板行**更新（状态/commit/遗留）；
3. **工作日志**追加（**必须注明开关态**+问题清单）；
4. **决策文件**（若有需拍板项，注明窗口）；
5. **commit**（本轮全部产物，单轮粒度）。

## 六、判定口径

| 维度 | 通过标准 |
|---|---|
| AI 会用 | 出手 >0 且跨种子非孤例 |
| 效果落地 | 对应信号/事件命中（探针捕获），非仅出手 |
| 组合协同 | 按技能语义（合击=窗口齐发/融合=条件聚合/拦截=受击分支） |
| 玩家通道 | 原作说明操作 = 原作描述效果 |
| 健康红线 | 卡死=0、模拟危险=0、接球率红线 |
| **双通道任一不过 = 该技未完成**（回修，不降标准） |

## 七、窗口纪律（四戒）

1. **不擅自批量新增数据**——技能/元灵/任何数据条目，先列清单报主人点头；
2. **不碰他人未提交文件**——开工三查（看板→git→mtime），他人 WIP 在手即等待；
3. **不擅自改基线/主线参数**——拍板制，实验一律沙盒；
4. **报告必注明开关态与测试路径**——面板所见与实测必须同一套。

## 八、主人参与点（全程五次）

1. 权重/数值/参数拍板；
2. 实机观感终验（通道3 与观感项）；
3. （学打法时）亲自打局；
4. 里程碑门放行；
5. 开关还原确认。
