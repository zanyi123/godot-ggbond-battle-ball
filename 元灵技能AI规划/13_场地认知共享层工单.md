# 13 场地认知共享层工单 —— 场地划分/白线规则入库，技能AI与球员AI共用

> 主人需求（2026-09-26）：技能AI要学习场地划分/场地白线的规则与认识，**方便优化笨笨的球员AI走向**。
> 执行窗口：**布场窗口（主责，机动复用：场地/位置域）**；集成窗口配合（ctx组装+ai_manager 走位消费）。
> 关联：14号工单（外场失效）与其同源——外场/内场划分语义正是本工单知识库的一部分，两单衔接。

---

## 一、现状盘点（2026-09-26 核实）

| 资产 | 已有 | 缺口 |
|---|---|---|
| `field_zone.gd` | get_zone_at/is_in_playable_area/中线与边界违规判定/inner_center/转移流 | 只有"规则执法"视角，无"知识供给"视角 |
| 白线 | 3D 白线双轨（P3 22/22） | 白线只是视觉，AI 不可查询 |
| ai_manager | clamp_to_outer_field/hold_range/阵型模板/球吸引 | 走位用散落的自算几何，"笨"（贴墙/卡线/绕远）无场地语义可依 |
| 波D 放置原语 | 六种放置语义（goal_ball_line 等） | 全是即时几何推算，不知道白线/区域语义 |
| spirit_ai ctx | 感知字段齐全 | **零场地字段**（my_zone/line_distances/goal 均散落常量） |

**架构定位（主人需求的正确解法）**：不是"技能AI学会后去教球员AI"，而是**场地知识做成共享层，两边都从这一个模块取**——技能AI（放置/目标）、球员AI（走位/站位/避障）同一真相，单一来源。

## 二、设计：场地知识库（field_knowledge 层）

在 field_zone.gd 基础上扩展（不新建平行模块，避免第二真相）：

1. **区域语义表**：内场 / 外场A / 外场B / 中线 / 球门区 / 隔离墙——每区：语义名、边界多边形、通行规则
2. **关键位置查询**：我方/敌方球门、发球点、外场入口、隔离墙线段
3. **几何查询 API**：`dist_to_line(pos, line_id)`（到任意白线距离）、`zone_of(pos)`、`would_cross_line(from, to)`（走位是否越线）、`nearest_gate(pos)`（最近通道口）
4. **规则问答**：某点在界内吗 / 该走位是否违规 / 外场球员能回到内场吗（救援规则接入点）

## 三、供给与消费（纪律延伸）

- **供给**：照 06§4.2 ctx 单口模式——ctx 增补场地字段（`my_zone`/`goal_own`/`goal_enemy`/`line_distances`/`in_outer`），manager 组装，原语禁直连（红线延伸条款）
- **消费①技能侧**（布场窗口）：波D放置语义升级——墙/区域落点可表达"贴己方白线内侧""堵外场入口""球门区纵深"等语义
- **消费②球员AI侧**（集成窗口，主人要的"优化笨笨走向"）：阵型站位/避障/拦截预判改用 zone 查询——预期收益：卡线死循环残余、贴墙抖动、外场绕远三类现象按场地语义修正

## 五、验收

1. 知识库 API 套件全绿（区域归属/白线距离/越线判定正反例）
2. 波D：同场景下放置落点对比（改造前/后截图或坐标进看板）
3. 球员AI：卡线/贴墙/绕远三类现象在观察期统计下降（有 match_stats/状态切换指标可对照）
4. 实机：主人目验走位"变聪明"
5. 门禁：全关逐位 + 全开危险=0
