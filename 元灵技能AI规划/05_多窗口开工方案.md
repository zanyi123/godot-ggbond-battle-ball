## 二、防越界机制（对 04 §五八条纪律的操作化）

1. **白名单制**：每个窗口能改什么，写死在它的开工提示词里（§三模板）。白名单外一律只读；规划文档只归规划窗口
2. **热点单写者**：`spirit_ai_manager.gd` / `ai_manager.gd` / `skill_state_manager.gd` 同一时刻只归一个窗口（看板可查）；实施窗口发现"必须改热文件"→ 停手上报规划窗口开集成工单，**不自己动手**
3. **开工三查**：看板 → `git status` → 目标文件 mtime。他人有未提交改动 = 不动 + 上报
4. **认领先于动工**：看板写名+时间才碰文件；行带 commit hash 追溯
5. **完成即 commit**（单波粒度）；验证资源排队（跑 sim/全量回归前看板标"验证中"）
6. **stash 禁令**：对任何文件（尤他人白名单内）严禁 stash/checkout/rebase；实验回退用临时目录副本（2026-09-25 实录教训）
7. **越界处置**：发现越界改动不上报不回滚就是二次违规；回滚由规划窗口执行，当事人只上报
8. **时差兜底以 git 为准**：看板状态与 git 矛盾时，git log 是唯一事实，主人仲裁

## §追加 编制 v2（2026-09-26 主人裁：编制冻结+复用制+防幻觉纪律）

**背景**：10号平台/12号深度测试曾拟新开窗口，与原定编制（7位）膨胀失控，主人叫停。

### 编制冻结令
- **未经主人在看板批准，任何窗口不得新增编制位**；新工单一律塞进现有编制
- 每份新工单头必须写明【给哪个窗口】（主人规）

### 窗口生命周期：完成 → 待命 → 机动复用
波次窗口完成任务后**不注销**，转为机动实施位，按各自的单写者领域复用：

| 编制位 | 状态 | 机动领域（单写者延续） |
|---|---|---|
| 规划窗口 | 常驻 | 仲裁/规约/文档/看板 |
| 集成窗口 | 常驻 | 接线+整体测试+诊断修复（manager/handler链） |
| 增益窗口 | ✅待命（机动） | registry/开关/描述符定价域 |
| 生存窗口 | ✅待命（机动） | 事件钩子/状态效果域 |
| 布场窗口 | ✅待命（机动） | 场地/位置语义域 |
| 操球窗口 | ✅待命（机动） | **skill_state_manager/操作方式域**（12号OP_COMBO归此） |
| 拾遗窗口 | **编制取消** | 波E小活由机动窗口顺手做，不占编制 |
| 平台窗口 | 工具位（已存在，不再扩大） | 平台维护+实机验证支持 |
| **平衡分析窗口** | ✅ 新增（主人 09-30 批准） | 参数调整→游戏平衡影响的量化实验（能量/CD/前摇等变量扫描），参考结果写进技能清单（21号职责书） |

### 防记忆错乱/幻觉三纪律
1. **文档是唯一真相，窗口记忆只是缓存**——重派任务时指令强制【重读工单全文+看板自己那行】，丢弃与本任务无关的旧上下文假设
2. 每窗口边界=看板行+白名单；完成即销项；复用不以【我记得】为准，以重读为准
3. 窗口跑门禁/改动前必查 git status 与看板（开工三查），发现状态与记忆不符=先停下核对文档

### 补规（2026-09-26 主人裁）：工单必备节=【窗口分工表】
- 每份工单（新立或修订）必须含一节表格：**窗口 | 负责内容 | 文件白名单 | 交接**——工单本身就是分工载体，窗口读单即知自己那份，不依赖任何窗口的记忆或编制知识
- 编制 v2 的机动复用只是人员背景说明；**分工的落点永远在工单内的分工表**
- 已补齐：11（§五）、12（§六）；此后新工单照此办理
