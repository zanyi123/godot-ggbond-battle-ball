## 二、挂接点设计（唯一分发点，无 destructive 改动）

### 2.1 DEFEND_INTERCEPT —— `player.gd:1177 take_damage()` 前置口（唯一）

```
位置：take_damage 内、无敌检查（:1191）之后、易伤倍率计算之前
新增分发块（一个）：
  若本玩家处于防御拦截态（锅装备态/快牙撕咬守鲨在场——状态来源=23c 装备态与 F1 守鲨标记，
  经 player 侧轻量标志位 is_defend_intercept_ready 读取，不由事件系反向查询）：
    emit DEFEND_INTERCEPT {defender=self, attacker, blocked_damage=amount, item=拦截源}
    return {"damage": 0, "effect": "none", "intercepted": true}
  （限度逻辑=拦截源自管：锅=耐久次数、撕咬=限度内停球超限改线，均由各自实体在收到
    DEFEND_INTERCEPT 后自行扣减/处理，take_damage 只管"拦与不拦"一个布尔判定）
```

### 2.2 DEFEND_ATTRIBUTE_BREAK —— `ball.gd:525/532` 命中判定口（唯一函数内）

```
位置：take_damage 调用前的命中判定处（ball.gd 两处同函数族）
新增分发块（一个）：
  来袭元素=_attacker_element()（ball.gd:1512 既有）；
  若被击者处于"撕咬防御态"且来袭 element=="雷火"：
    emit DEFEND_ATTRIBUTE_BREAK {defender, attacker, element, skill_id}
    本次命中瓦解：伤害归零 + 球按撕咬参数改线/停（超限逻辑同 2.1 由撕咬实体自管）
```

### 2.3 wire_sources 扩展（一处）

```
event_bus.gd:69 wire_sources 追加一段（照 ball_caught 同款守卫）：
  遍历 players：p.has_signal("ball_caught") 已有；新增无需——
  SUMMON_*/ITEM_*/BALL_FORCED_CONTROL 均由 manager/granter/消费端直接 emit_event，
  不经 wire_sources（它们不是节点信号转发，是系统级通知）——wire_sources 仅需为零改动确认。
```
