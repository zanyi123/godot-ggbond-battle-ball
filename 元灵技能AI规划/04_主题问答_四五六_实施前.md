## 二、主题⑤：通讯与信息获取（个体/团队时机 + 玩家↔AI、AI↔AI 时机传递）

### 2.1 现状盘点（01 审计结论，2026-09-25）

- ai_communication 共 **6 种消息**：老3种（DEFEND_ALERT/PASS_TO_ME/DONT_PASS）ai_manager 正常消费；技能层3种中 NEED_BUFF/BUFF_ON_YOU 由技能AI自收自用（评分因子 ×1.4/×1.25），**SKILL_READY 有查询接口但全项目零消费**；T5.4（球员AI收 BUFF_ON_YOU 更敢进攻）确诊未实施
- **玩家↔AI 通道不存在**；信息获取侧技能AI仍是上帝视角（01 #1 残余：评分侧全量收口未做）

### 2.2 信息获取侧（先于通讯）

1. **感知收口**：技能AI评分/目标侧全量走 `get_ap_for_player` 感知出口（02 已建口，01 #1 大项收尾）——"能根据场上球员状态判断时机"的前提是状态获取合规
2. 数据面已备：队友需求快照（needs_assistance）、团队短板分析、支援/攻击目标评分公式

### 2.3 消息协议 v2（类型化负载 + 三类语义）

**负载格式**（扩展现有 last_msg_type 单值）：`{type, sender, urgency, expire_cycle, position, related_skill_id}`，TTL/冷却全部周期计数化（确定性，照 02 范式）。

| 语义 | 消息 | 发送方 | 消费方与效果 |
|---|---|---|---|
| 请求 | NEED_BUFF（细分 NEED_HEAL/NEED_SHIELD） | 残血/缺盾球员 | 对应支援技评分×1.4（已有）+ 细分路由 |
| 通知 | SKILL_READY | 大招就绪者 | **补消费**：队友进攻分↑+接应走位（ai_manager 新增分支） |
| 通知 | BUFF_ON_YOU | 给buff后告知 | **补 T5.4**：球员AI更敢进攻（ai_manager 消费） |
| 邀约 | **COMBO_SETUP**（新） | 连招 setup 技释放者，带 skill_id+窗口 | 持 finisher 技的队友评分×(1+bonus)，窗口期内生效（⑥联动） |
| 预警 | **ENEMY_ULT_WARNING**（新） | 视野内见敌激活大招者，短TTL | 持 cc_immune/闪避类技评分窗口打开（B波 cc_immune 的时机来源） |

### 2.4 玩家↔AI 通道（全新，同一总线）

- **玩家→AI**：快捷键/备战面板发请求（"要球"已有 PASS_TO_ME 类似物、"请求掩护/增益"新增），经同一消息总线，AI 按消费规则响应——**AI 不需要新感知通道，只是消息来源多了人类**
- **AI→玩家**：复用现有通讯气泡显示（"防守!"等已上屏），新增消息自动获得显示；重要邀约（COMBO_SETUP）可加 HUD 提示（13 批次 status 组件可挂）
- 实现载体：`ai_communication.gd` 单口扩展（消息类型枚举+负载字典），禁散落直调

## 四、实施前问1：怎么提高开发效率（多窗口并行，多方案展开）

| # | 方案 | 展开 |
|---|---|---|
| 1 | **进度看板认领制** | `元灵技能AI规划/进度看板.md`：表（波次/范围/认领窗口/状态/commit/时间戳）。开工=先看板后动工；只更新自己的行；行带 commit hash 供追溯 |
| 2 | **原语数据化分文件（消灭热点，关键设计）** | 原语表放 JSON（`data/systems/spirit_ai/`），原语函数按波分文件（`scripts/battle/spirit_ai/primitives_a.gd` 等），`spirit_ai_manager.gd` 只留集成点——**现状全波共用一个 1385 行热点文件的冲突根源被结构性消除**，各波文件互斥天然并行 |
| 3 | **接口冻结先行** | 动工前先落一个"原语接口规约"小工单：JSON schema（字段名/类型/单位）+ 原语函数签名 + 注册方式。各波按规约并行，集成期零磨合 |
| 4 | **数据先行** | 每波先落 JSON 原语表（纯数据零冲突、可全并行），函数实现跟上；评分效果可先用现有三大类兜底跑通链路再精化 |
| 5 | **波次独立验收** | 每波自带回归套件，验收不依赖其他波（数据驱动使然）；通用验收脚本一个（跑全套件+门禁+randf检查），各波复用 |
| 6 | **验证窗口专职化** | sim 门禁/全量回归由单窗口跑（看板"验证中"标记），避免并行跑 sim 互相踩（本机资源+结果可读性） |
| 7 | （可选）技能AI行为可视化 | dev 面板加"技能AI决策 dump"（当帧各技评分/胜出者/原因），调参效率倍增；归 13 批次 UI 轨道 |

## 五、实施前问2：防时差/防并发冲突（保证窗口查看文件时不被修改）

**八条纪律**（含今日实录教训）：

1. **开工三查**：看板 → `git status` → 目标文件 mtime（有人未提交改动=不动+上报）
2. **认领先于动工**：看板写名+时间才碰文件
3. **热点单写者**：spirit_ai_manager.gd 同一时刻只归一个窗口（方案2分文件后此热点大幅缩小）
4. **完成即 commit**：单波粒度提交+看板同步——未提交的工作是最大的冲突源
5. **共享验证资源排队**：sim/全量回归同时只一个窗口（看板标记）
6. **严禁对他人在改的文件做 stash/checkout/rebase**：今日实录——02 工单 A/B 对照 stash 把并行窗口未提交改动一起收走（幸有备份恢复）；**实验性回退一律用临时目录副本，不用 stash**
7. **日志只追加**：工作日志/规划文档各写各段，不删不改他人段落
8. **时差兜底以 git 为准**：看板行带 commit hash，两人状态矛盾时以 git log 为准，主人仲裁

## 附录：一页速查（人话版）

**主题④ 说人话**：给 103 个技能逐个定"什么时候放、放给谁、怎么操作、怎么算分"——已按性质归成 12 类填好这张表，再按风险从低到高排成 5 批做：**第1批**纯增益（加攻加防攒能量，39个标签，最安全）；**第2批**保命和控制（开盾/回血/眩晕，要加"挨打瞬间反应"）；**第3批**球的特殊飞行（追踪/引导/回收，要 AI 学会操作技能）；**第4批**放墙放区域（位置怎么选）；**第5批**疑难杂症（复制/地形/幻影，10个左右，逐个做）。

**主题⑤ 说人话**：队友之间会"喊话"，但现在喊话一半没人听（"我技能好了"喊了没人理）、玩家也没法指挥 AI。修法：喊话带上详细信息（谁喊的/多急/多久过期），把没人听的补上人听，加两种新喊话（"我起了手谁来连招"/"敌方开大了小心"），**玩家也能用快捷键喊话指挥 AI**——AI 不用多长眼睛，只是多了个人类队友在频道里说话。

**主题⑥ 说人话**：全队配合的骚操作——一起集火同一个人（谁被标记全队打他更疼）、连招接力（我减速了你接眩晕）、抓住敌方破绽全队爆发——**最后再做**，先把单兵的地基打好。都是轻量改法，不搞复杂的战术规划器。

**实施前两问 说人话**：多窗口一起干活不吵架的办法——墙上贴任务认领表（谁领了啥一眼看清）；把共享的那份大代码文件拆成每人一个的小文件（从根上不抢）；干完一小块立刻提交存档；跑模拟测试排队不抢机；**谁都没提交的文件，别人绝不碰（今天就有个真实教训：做实验差点把别人改一半的东西收走）**。
