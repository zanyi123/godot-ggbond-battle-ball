## 二、数据与接口设计（对齐骨架，接口零自造）

### 2.1 ZoneType.ENERGY_PATH（第7型）

```
field_effect_zone.gd 枚举追加 ENERGY_PATH
ZONE_COLORS: 青蓝流光（fill a≈0.2 / border 亮青）——可视归美术可调
ZONE_NAMES: "能量快道"
```

### 2.2 setup 参数扩展（params 键，全部带默认值 fail-closed）

| 键 | 类型/默认 | 语义 |
|---|---|---|
| `path_from` / `path_to` | Vector2 / Vector2 | 条带两端点（世界坐标）；缺任一 → 回落矩形模式（from=zone中心，to=from+(0,-1)）= 退化短道，不崩 |
| `path_width` | float / 48.0 | 条带宽（固定参数，原作视觉带） |
| `energy_per_sec` | float / 2.0 | 持续注能速率（**从施法者 spirit_energy 扣**——原作"持续注入能量"） |
| `path_buffs` | Dictionary / {speed_mult:1.3, energy_cost_mult:0.5} | 路径增益参数表（**原样下发 summon_manager**，zone 不解释内容——消费方是 F1 水鲨鱼） |
| `owner_id` / `owner_team` | int / String | 注能扣减主体+友军判定（敌队不走路径增益——与 caster_team 先例同构） |

### 2.3 条带几何（纯函数，套件可测）

- 形状：RectangleShape2D 长=|to-from|，宽=path_width，Area2D.rotation 对齐连线方向——**零新形状类**，复用矩形碰撞
- `contains_point(pos) -> bool`：点→线段投影 t∈[0,1] 且垂距 ≤ width/2（纯几何，供 summon_manager 查询式调用）
- `direction() -> Vector2`：from→to 单位向量（路径方向语义）

### 2.4 持续注能（tick，照 HEAL 先例）

- `_process_energy_path_tick(delta)`：`owner.spirit_energy -= energy_per_sec * delta`（走 player 既有能量通道，不新开口）
- **能量耗尽 → 路径提前消散**（推荐语义：路径由持续注能维持，原作一致性）；`owner_id` 失效/被击败 → 同样消散
- tick 确定性：delta 累计（与 heal_tick 同构），无 randf

### 2.5 对 summon_manager 的通知口（⚠骨架修正点，两案供主人裁）

骨架原文"挂接：zone_enter/exit 事件（既有）通知 summon_manager"——实测无现成对外事件，两案：

| 案 | 实现 | 优/劣 |
|---|---|---|
| **A 事件转发（贴骨架，推荐）** | energy_path zone 新增两个信号 `entity_entered_path(entity)` / `entity_exited_path(entity)`（body_entered/exited 过滤 summon 实体后转发）；summon_manager 订阅 manager 层统一口（field_zone_manager 加 `energy_path_signal` 聚合转发，**F1 只订一处**） | 实时贴合"鲨鱼进快道获增益"语义；挂接点唯一（manager 一处转发）；F1 未建期间信号无人订阅=零副作用 |
| B 查询式 | summon_manager 移动实体时调 `contains_point` | 零信号；但每实体每帧查询，实体多时开销大，且"进入/离开"沿难定义 |

**推荐 A**。纪律：两信号只对 summon 实体（F1 定义的 summon 分组）广播，不涉球员/球（球员走路径不获增益——原作增益对象=水鲨鱼；若主人裁"球员也加速"改 path_buffs 消费方即可，zone 侧不变）。

### 2.6 可视（通道②既有绘制体系）

条带色块（旋转 ColorRect）+ 边线 + 方向箭头（2~3 个沿线三角）+ 剩余时长标签（复用 _timer_label 惯例）——形状绘制照 VISION/HEAL 先例，表现层细节归美术可后调。
