## 二、Phase 1：场地建模（小样测试）

### 2.1 目标

创建 3D 场景场地，参考动画截图风格，包含绿色草地、6块可调节反弹墙、外围街道。验证 MCP 工作流可行性。

### 2.2 角色尺寸基准（来自 player_3d_test.gd）

| 参数 | Godot/Blender 单位 | 说明 |
|------|-------------------|------|
| 角色高度 | ~50 | PROXY_MODEL_HEIGHT = 49.86 |
| 角色缩放 | 70 | PROXY_SCALE |
| 持球高度 | 55 | BALL_CARRIED_3D_Y |
| 球飞行高度 | 30 | BALL_FLIGHT_3D_Y |
| 球缩放 | 30 | BALL_SCALE_3D |

**单位说明**：3D世界单位 = 游戏像素 1:1

### 2.3 场地规格（参考动画截图）

| 对象 | 尺寸（单位） | 说明 |
|------|-------------|------|
| 主场地 | 1300 × 780 | 绿色草地材质 |
| 外围街道 | 待定 | 深色铺装，自然过渡 |
| 反弹墙 | 见下方 | 6块，模块化设计 |

### 2.4 反弹墙详细规格

**布局**：长方形球场，长边2块+宽边1块（共6块）

```
        ┌──────────────────────────────────┐
        │                                  │
        │  ┌──┐                    ┌──┐   │
        │  │墙│                    │墙│   │  ← 长边：各2块
        │  └──┘                    └──┘   │
        │                                  │
        │         绿色草地                 │
        │                                  │
        │                                  │
        │  ←──墙──→              ←──墙──→  │  ← 宽边：各1块
        │                                  │
        └──────────────────────────────────┘
        ←────── 1300 单位 ──────→
```

**单块墙参数**：

| 参数 | 规格 |
|------|------|
| 高度 | 100 单位（2倍角色高） |
| 位置 | 贴近场地边缘内侧 |
| 材质 | 半透明青色发光 |
| 设计 | **模块化，可单独调节** |

**模块化设计要求**：
- 每块墙作为独立物体
- 可单独调整位置、大小、高度
- 便于后续物理碰撞调试

### 2.5 执行步骤

| 步骤 | 操作 | 预算 | 验收标准 |
|------|------|------|----------|
| 1 | Blender 创建场地几何体 | 200 | 草地+外围街道正确建模 |
| 2 | 创建6块反弹墙（模块化） | 150 | 每块独立可调节 |
| 3 | 配置材质/发光效果 | 100 | 半透明青色发光 |
| 4 | 导出 GLTF 文件 | 50 | 文件无错误 |
| 5 | Godot 导入+位置校对 | 200 | 坐标误差<5单位 |
| 6 | 截图验证 | 50 | 视觉确认正确 |
| **合计** | | **750** | |

### 2.6 验收标准

- 场地尺寸：1300 × 780 单位
- 反弹墙：6块，高100单位，位置准确
- 模块化：每块墙可单独选中调节
- 材质：草地绿色、反弹墙青色发光
- 外围：深色街道自然过渡

### 2.7 失败回退

- 坐标偏差大：手动微调，不超过2次重试
- GLTF 导入错误：改用 OBJ 格式
- 材质不兼容：使用基础材质
- 反弹墙位置错误：单独调整每块墙

## 三、Phase 2：角色绑骨修复

### 3.1 问题诊断

当前状态：`glb静态模型 + fbx动作动画 → 绑骨不匹配`

### 3.2 解决方案

| 方案 | 操作 | 成本 | 质量 |
|------|------|------|------|
| **A. 格式统一** | GLB/FBX → GLTF | 400 | ⭐⭐⭐⭐ |
| **B. 自动绑骨** | Blender Rigify/自动绑骨 | 500 | ⭐⭐⭐ |
| **C. 权重调整** | 手动+AI辅助调权重 | 200 | ⭐⭐⭐⭐ |

### 3.3 执行步骤

| 步骤 | 操作 | 预算 | 验收标准 |
|------|------|------|----------|
| 1 | 分析现有模型/动画格式 | 100 | 确认格式详情 |
| 2 | 转换为统一 GLTF | 200 | 无数据丢失 |
| 3 | 自动绑骨 | 300 | 骨架结构正确 |
| 4 | 权重调整 | 200 | 无明显穿帮 |
| 5 | 导出验证 | 200 | Godot 中可驱动 |

### 3.4 降级方案

如果自动绑骨质量不达标：
- 使用简化绑骨（仅根骨骼+四肢）
- 或保持现状，Phase 3 中使用原始动画播放

## 六、积分控制规则

### 6.1 三条强制规则

1. **事前报预算**：每步操作前必须列出预计消耗，等待用户确认
2. **事后报消耗**：每步操作后报告实际消耗，更新累计
3. **80%硬停**：累计消耗达 4000 积分（总预算80%）时强制暂停

### 6.2 累计消耗追踪

| 日期 | Phase | 操作 | 预算 | 实际 | 累计 | 状态 |
|------|-------|------|------|------|------|------|
| - | - | 初始 | - | - | 0 | - |
| - | 1.1 | 创建场地 | 200 | - | - | 待执行 |
| - | 1.2 | 配置材质 | 100 | - | - | 待执行 |
| ... | ... | ... | ... | ... | ... | ... |

### 6.3 叫停机制

- 用户可在任何步骤后叫停
- 叫停后已消耗积分不退回
- 叫停后可随时恢复执行
