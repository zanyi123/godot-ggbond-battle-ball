## 二、四步工作流详解

### 步骤① 拓扑修复 —— 可实现度 ★★★★★（已验证）

- **做什么**：合并重合顶点(0.001m) → 重算法线 → 删游离元素。治"黑斑碎纹"。
- **命令**：
  ```bash
  blender --background --python tools/repair_mesh_topology.py -- 输入.glb|fbx 输出.glb
  ```
- **验收[Godot]**：双击修复版 GLB，看头发边缘/裙摆褶皱/手臂内侧——黑斑消失、造型无缺损。
- **实测数据（player2）**：base.glb 顶点 889674→532380，非流形边 272316→4808（-98%）。
- **风险**：低。合并阈值 0.001 保守；低模（low 系列）可能残留深度损伤（low_gu_v2 非流形边仅降 102），
  属进阶档问题，不阻塞本步。
- **player2 状态**：✅ 完成（base + low_gu_v2 两份修复版在 `player2/修复/`）。

### 步骤② 杯型手 —— 可实现度 ★★★★☆（80%）

- **做什么**：右手网格塑成半握杯形（持球手型），烘进网格。左手不动。
- **怎么做**（MCP 连 Blender 后逐步执行，每小步让主人在 Godot/视口确认）：
  1. 导入 `修复/player2_base_修复版.glb`
  2. 定位右手：权重主导为 `RightHand` 的顶点簇（约1182个，今晚已验证可稳定识别）
  3. 塑形：比例编辑(Proportional Editing, 关联半径≈手长0.24m)下，对手背顶点做
     向掌心方向的收拢+下压，形成"托球碗"状。**每次变形量≤15%，改一次存一版**
  4. 导出 `player2/修复/player2_base_手型版.glb`
- **验收[Godot]**：手呈自然托碗状；放一颗球（缩放对比）在掌心不悬空不穿透。
- **风险**：盲调变形方向可能出怪形（任务2教训）。**缓解**：每次变形后必须截图/存档给主人看，
  不连续盲改；变形量从小到大迭代。
- **依赖**：①完成 ✅。
- **player2 状态**：✅ Blender侧完成（2026-09-15 深夜，GL 离屏渲染目检 4 轮迭代 + 球体对比通过），**待主人 Godot 目检终验**。
- **实测工艺（批量 8 人复用，2026-09-15）**：
  - base.glb 无骨架 → 几何定位：T-pose 掌心朝下（局部-Y），角色右手 = X- 侧；
    腕线 x≈-0.38、指尖 x≈-0.542、掌心中心局部 (-0.44, 0.547, 0.022)、手区高度带 y∈0.46~0.64
  - 变形 = 绕腕枢轴 (-0.38, 0.547, 0.02) 的 X 轴向 +Y 卷角 **累计 45°**（4 轮 × 15%/轮，
    smoothstep 权重腕 0→指尖 1）+ 指尖 z 向掌心线内收 15%（掌心 z=0.0217）
  - 球体对比：r=0.10 测试球（球/身高比例）坐指碗，贴掌不悬空不穿透
  - 产出 `修复/player2_base_手型版.glb`（回环复核：单对象、bbox 一致、原件零接触）

### 步骤③ 共有动作导入 —— 可实现度 ★★★☆☆（60%，四步中最高风险）

- **做什么**：让静态模型动起来（原地持球/跑动持球/投球/接球）。
- **关键架构决策（需主人拍板）**：
  - **路线甲（已验证过一次，2026-07-17）**：用带骨架的动画 FBX 做渲染本体（白模），
    把 base.glb 的贴图通过 material_override 迁移上去（`_apply_pbr_materials_to_fbx` 已有代码）。
    优点：骨架+动画现成。缺点：网格是 FBX 白模那套。
  - **路线乙（理想但未验证）**：base.glb 网格直接绑到动画骨架（网格换皮）。
    风险：绑定点/rest 不匹配会"撕成碎片"（今晚水母教训）。
  - **建议**：先走路线甲（有成功先例+代码存在），路线乙作为后续优化。
- **怎么做（路线甲）**：
  1. 导入共享动画 FBX（如 `actions/jog.fbx` 或 avatars 四件套）
  2. 对 FBX 网格执行步骤①修复 + 步骤②手型（同样工艺）
  3. `player_proxy_3d.gd` MODEL_MAP 配置 `model_fbx` 路线（代码已支持）
  4. 验证动画播放 + 贴图迁移效果
- **已知坑（全部踩过，见工作日志2026-09-15）**：
  - 四元数双覆盖：w<0 的键轴角分解变巨转，操作前必须最短表示归一化
  - 混合旋转模式导出污染：动作里 quat+euler 并存会让 Godot 与 Blender 解读不一致，
    导出前只保留骨骼 rotation_mode 对应的一种
  - MCP 远程上下文：use_selection/object.delete 可能静默失败，操作后必须复核
- **验收[Godot]**：跑动时手臂自然摆、裙摆/衣服不撕裂、贴图正确。
- **依赖**：②完成（手型要在渲染本体网格上）。
- **player2 状态**：⬜ 待做（依赖②）。

### 步骤④ 球挂点校准 —— 可实现度 ★★★★★（90%）

- **做什么**：把 HandProxy 的写死偏移 `Vector3(8,30,0)` 换成实测杯心坐标。
- **怎么做**：
  1. 步骤③后，在 Godot 运行时打印持球手骨骼/掌心的全局坐标（或 Blender 量取后按
     单位制换算——注意 ModelSlot scale=PROXY_SCALE，须换算到代理空间）
  2. 更新 `player_proxy_3d.gd` HandProxy 偏移（建议做成 MODEL_MAP 内每角色可配，
     而非全局写死——不同角色手位有差异）
  3. 球大小微调：当前球偏大，按掌宽比例出缩放建议值（球模型本体不动）
- **验收[Godot]**：持球动画下球贴掌心不悬空；跑动跟手。
- **依赖**：③完成（球要跟手骨运动，雕像模式下无意义）。
- **player2 状态**：⬜ 待做（依赖③）。

## 五、失败应对手册（症状→处置）

| 症状 | 根因 | 处置 |
|---|---|---|
| 手臂甩上天/章鱼 | 四元数双覆盖 | 键值最短表示归一化后重算 |
| Godot 与 Blender 姿态不一致 | 导出混合旋转模式 | 清理只留 rotation_mode 对应曲线 |
| 模型变水母/碎片 | 骨架绑定 rest 不匹配 | 放弃网格换皮，走贴图迁移路线甲 |
| 改动"没生效" | MCP 静默失败 | 重新枚举对象清单复核，勿信返回值 |
| 截图纹丝不动 | 视口陈旧帧 | 请主人点窗口前台；或以 Godot 为准 |
| 黑斑回归 | 非流形边残留 | 进阶档：补洞+成流形（需目检迭代） |
