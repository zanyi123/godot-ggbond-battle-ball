# 新球员模型处理 SOP（混元绑骨 GLB → 游戏可用）

> 2026-09-15 制定。来源：任务1/2 失败教训 + 任务4 修复试点成功经验。
> **铁律：模型层全部完成并验收后，才碰动画层。每步只在 Godot 验收。**

## 流水线（严格按序）

```
混元绑骨完成，拿到 GLB
   ↓
① 拓扑修复
   工具：blender --background --python tools/repair_mesh_topology.py -- 输入 输出
   内容：合并重合顶点(0.001) → 重算法线 → 删游离元素
   产出：xxx_修复版.glb（原件不动）
   验收[Godot]：黑斑碎纹消失，造型无缺损
   ↓
② 杯型手（持球手型，烘进网格）
   内容：右手塑成半握杯形，腰口以上的手臂保持原状
   验收[Godot]：摆球对比，持球观感自然
   ↓
③ 导入共有动作数据（共享动画库）
   内容：走路/接球/投球等骨骼轨道，挂到本模型骨架
   验收[Godot]：动作正常播放，杯形手在所有动画下保持
   ↓
④ 球挂点实测校准
   内容：量杯心世界坐标 → 更新 HandProxy 偏移（现为写死 Vector3(8,30,0)）
   验收[Godot]：球精确落在手掌中，跑动跟随
   ↓
球员正式完成，换入 assets/game_models/（改 MODEL_MAP 指向）
```

## 顺序依据（硬依赖）

- ① 必须在 ② 前：修复的合并顶点会吞掉手型细节，先雕后修 = 白雕
- ③ 必须在最后：模型层（①②）验收完才碰动画层，避免模型问题与动画问题混淆

## 血泪教训（2026-09-15，违反即重蹈覆辙）

1. **只信 Godot 实机**：Blender 数值验证（位移/包围盒/距离）与 Godot 实机表现可能矛盾，
   Blender 里"通过"不算通过
2. **盲调必败**：视觉向修改（手型/权重/姿势）没有目检就交付 = 必定翻车
3. **MCP 远程上下文会静默失败**：use_selection / object.delete 可能没生效，
   破坏性操作后必须重新枚举对象清单复核
4. **四元数双覆盖**：w<0 的键轴角分解会变 354°巨转，缩放/插值前必须归一化最短表示
5. **混合旋转模式导出污染**：动作里同时存在四元数+欧拉曲线时导出 GLB 会被
   Godot 解读出与 Blender 不同的姿态，导出前清理干净（只留骨骼 rotation_mode
   对应的那一种）
6. **原件永不覆盖**：每步产出新文件名，源文件只读

## 已知边界（2026-09-15 时点）

- 手型方案为"静态杯形"：因模型无指骨，所有动画下手型恒为杯状——Q版可接受
- 指骨级手指动画：需先有带指缝的模型源 + 可靠视觉反馈，暂缓
- 游戏 3D 当前为"雕像模式"（E11 外观模式无骨架动画），原地/跑动持球动画
  属于骨架路线目标，见 docs/3D场景回归Godot融合方案.md
