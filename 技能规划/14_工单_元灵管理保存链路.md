## 二、合法性校验规则（F5，防"空壳标签"重演）

1. **标签 id 必须存在于 tags_registry.json**（拼写错误=静默无效，历史铁律）
2. tag_params 的键与 registry 该标签 params 列表比对：缺失必填→阻断；多出→警告不阻断（向后兼容）
3. 元素 ∈ 六元素；type ∈ active/passive；数值范围（冷却≥0、能量≥0、百分比参数给合理上限警告）
4. id 唯一性 + 命名规范 `skill_<元素>_<序号>`（自动生成可改）
5. passive 必带 trigger.event 且事件名 ∈ event_bus 枚举
6. 校验失败：阻断保存并**在 UI 上红字提示具体原因**（不许静默）

## 三、持久化策略（预裁决，实施时可提异议）

- **直写 `res://data/spirits/skills.json`**（项目开发期 res:// 可写；保存后调 `DataManager.load_all_data()` 热生效）
- 写入保持 JSON 人类可读格式（与现有缩进风格一致——这文件是主人手改频率最高的数据文件）
- 备份依赖 git（数据文件在版本控制内，不做额外 .bak 机制）
- 导出发布期再迁移 user:// 方案（届时另立项，本批不做）
- 实施窗口若认为必须走 user:// 合并加载，**先停下来问主人**，不许自行改加载链

## 四、测试断言（≥8 项）

1. 新建→保存→`DataManager.load_all_data()` 重载→数据在且字段完整
2. 编辑→保存→重载→修改生效
3. 删除→重载→消失
4. 非法标签 id 被阻断且 UI 红字提示
5. 重复 id 被阻断
6. passive 缺 trigger 被阻断
7. 保存后文件仍为人类可读 JSON（格式断言）
8. **落盘清洁断言**：测试产生的临时技能条目在测试结束后全部清除（git diff skills.json 为空）
