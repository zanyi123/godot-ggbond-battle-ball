# 02 · 元灵技能原语规划（长期文档 · 账本与流程）

> 定位：**干活用的账本+操作手册**。新技能从一句话到代码落地的判断流程、原语覆盖表、缺口台账、产能路线、批次记录。
> 配套：系统链路细节/官方资料见 `01_原作元灵技能资料与链路适配.md`。
> 核心思想：**技能 ≠ 功能，技能 = 原语组合配方**。缺口只允许出现在原语层（有限收敛），技能层自由量产（纯数据）。
> 建立：2026-09-17。

## 一、新技能实现判断流程（操作手册）

### 1.0 入口：登记
任何新技能先进本文档 §6"技能清单接收区"登记拿编号，防口头需求丢失。

### 1.1 第一站：机制拆解——三问（任何技能都逃不出）

| 判定 | 选项 | 决定什么 |
|---|---|---|
| **Q1 作用对象** | 球 / 球员 / 场地（可组合） | 消费路线 → 分流B的改动清单 |
| **Q2 生效时机** | T1 释放瞬间 / T2 球命中时 / T3 球停触地时 / T4 事件触发(被动) | 挂接点 |
| **Q3 持续时间** | 瞬时 / 持续N秒(要duration，可能要tick) / 随球存活 | 参数结构 |

拆解结果翻译成原语组合，对照 §2 覆盖表。

**示例**：蔓藤缠绕 = 球员 + T2命中时 + 持续2秒 → `player_root(T2挂球)`。

### 1.2 第二站：查覆盖表 → 三分流

```
原语全命中 ───→ 分流A：纯数据工单（§1.3，约0.5会话/3~5个）
缺1~2个原语 ──→ 分流B：新原语工单（§1.4，约1会话/个，主人批）
框架装不下 ───→ 分流C：游戏化改写提案 → 主人拍板 → 回第一站
```

### 1.3 分流A：纯数据工单标准7步
1. `data/spirits/skills.json` 新条目，命名 `skill_<元素>_<序号>`
2. `tags[]` 填原语名（查 tags_registry.json）
3. `tag_params` 填数值——**以 handler 实际消费为准**（registry 参数表有已知账实不符；照抄同类已实现技能的结构最稳）
4. 填目标选取（self/enemies/allies/nearest_enemy）
5. 仅被动填 `trigger{event,condition}`（事件名查 event_bus 17枚举）
6. 查组合冲突（互反标签同用？_tag_priority 顺序合理？）
7. 测试：headless 断言 + 涉及比赛行为跑 run_sim

### 1.4 分流B：新原语工单——判定到代码步骤

> ⚠ **语义铁律（2026-09-19 主人定）**：原语工单的代码落实 = **技能释放机制（判定层）**——改的是比赛结算规则（伤害/球权/状态数值），与模型动作/特效显示**无关**。表现效果（3D 粒子/2D 图标/动作切换）归美术线（M2 特效/M4 动作）；判定层只需暴露**只读状态 + 信号**作为衔接接口。
> 例（护盾）：判定层交付 = handler case + player.gd 护盾槽 + take_damage 先扣盾再扣血 + `shield_value` 查询 + `shield_changed` 信号；盾环粒子/shield_break 特效/举盾动作（block_idle）= 美术线消费接口，不在工单内。
> 理由：判定层先落地，没表现技能也能完整工作（sim 可验证）；两层混做会重蹈"区域效果直改球员私有变量"覆辙。

**B1 按 Q1 定改动清单（全部属判定层）**：

| 消费路线 | 必改文件清单 | 风险 |
|---|---|---|
| 球类 | handler 加 match case → `_ball_mods` 加字段 → `ball.gd` 加消费点；**影响命中/停球必须评估 E7v2 球权交互** | 高（动球核心，最后做） |
| 球员类 | handler 加 case → `player.gd` 六层管道选层（数值=Buff层 / 控制=状态灯 / 持续=tick / 倍率=next_skill_mult）+ 暴露只读状态/信号 | 中 |
| 场地类 | handler 加 case → 三 manager 选一（障碍/区域/幻象）→ 定触发入口（鼠标放点/坐标注入/事件钩子） | 中低 |

**B2 三处同步登记（漏一处=空壳标签，历史教训）**：
- `spirit_tag_effect_handler.gd` match case
- 同文件 `_tag_priority` 优先级表
- `data/spirits/tags_registry.json` 注册条目

**B3 可触发性确认（2026-09-19 降级，原"AI 评分必填"）**：工单只要求确认新技能/原语**落入现有评分池**（spirit_ai_manager 有默认行为，探针确认+标注默认时机档），保证 run_sim 能触发它。**战术级技能 AI（意图联动/局面选技/角色风格/与球员 AI 信息交流=「AI 真实球员」）整段移出本规划，未来单独立项为大工程体系**——在此之前 sim 数据注明"AI 时机为默认档"。

**B4 表现规格移交项（非本工单范围，移交美术线）**：工单末尾附"表现规格"三行——五阶段取哪些/挂哪（caster/ball/impact_point/field_zone）/元素色——供美术 M2/M4 排产，本工单不做。

**B5 测试**：原语级 headless 测试（仿 test_buff_manager）+ 动 ball.gd/player.gd 必跑 `./run_sim.sh` 危险总数=0（判定层完整可验证，无需表现层在场）。

### 1.5 分流C：游戏化改写
官方效果现有玩法框架装不下（如"吸收对手技能"）→ 出改写提案（保风味换机制）→ 主人拍板 → 回第一站。

### 1.6 验收契约（所有分流共用）
- headless 断言全过
- 动 ball.gd / player.gd / AI 相关 → run_sim.sh 危险总数=0（对比 sim_results/baseline.json）
- 表现：2D 轮廓自动；3D 粒子未有→记 01 文档缺口#8
- **回写账本**：§2 覆盖表打勾 → §6 排产状态 → §7 批次记录 → 工作日志

## 四、产能模型与分期路线图

**150 技能 ≠ 150 份工作**：
| 层 | 数量 | 成本 |
|---|---|---|
| 原语基建 | ~15 | 一次性 10~15 会话 |
| 量产工具链（表格导入+批量验证） | 1套 | 一次性 2~3 会话 |
| 技能本体 | ~135 | 原语齐后填表，10~20个/会话 |
| 数值平衡 | 滚动 | run_sim 指标自动化兜底 |

**复用率依据 70~80%**：40 队技能大量同构（属性强化/投射/防御变体），换皮=改数值+元素配色（Binbun 特效包 6 元素共用模型换 6 套色）。

| 版本 | 内容 | 规模 | 预估 |
|---|---|---|---|
| **V1 技能框架成型** | 修 `_ball_mods` 地基 + 原语#2区域触发 + **原语#4护盾** + 主角队18技（14个A类+火凤燎原/冰天雪地/弹性触手/被动1） | 18技能 | 4~6会话 |
| **V1.5** | 原语#10叠层印记（V2麒麟队包前置） | 基建 | 1会话 |
| **V2 主角团特色+首队包** | 哈默迪进化技（元灵模式数据化）+ 萝莉/黄三郎队包 + V2原语按需（#12/#13/#15/#16/#11/#14/#5/#3） | +10~15 | +3~5会话 |
| **V3+ 队伍包滚动** | 每版一队 10 技（复用70%+，新原语1~2个）+ 二批复制系（黑洞队包前置） | +10/队 | +2~3会话/队 |

**长期风险两条**（非工作量）：①数值膨胀→sim指标兜底+原语预算限流；②AI 时机为默认档（战术级技能 AI 未立项）→ sim 结论注明"可触发性验证"口径；「AI 真实球员」（技能×意图联动/局面选技/角色风格/与球员 AI 信息交流）= 独立大工程体系，技能池成型后（V2 后）单独立项，不在本规划范围。
