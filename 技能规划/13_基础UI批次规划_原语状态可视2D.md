# 13 · 基础 UI 批次规划：原语状态可视（2.5D 简约版）

> 定位：原语可验收性的基础反馈层——**看得出生效没生效**。与美术 M2 的高阶特效（粒子/动作/配色）分界：本批 = 判定状态的可见性，M2 = 观感升级。
> 载体拍板（2026-09-21 主人确认）：**2.5D（2D 界面层）**
> ⚠ **2026-09-24 修正（主人指出）**：2.5D 仅适用于**屏幕空间 HUD 件**（状态图标条/层数/充能点——永远叠在画面上，与显示模式无关）；**世界空间件**（盾弧面/地面圈/预览路径等场景内反馈）必须跟随显示模式 **3D 主/2D 兜底**（玩家默认 3D，2D 层画的场景反馈看不见）。13-C 盾弧面改 3D 盾体（障碍实体自带模型+换色）；地面圈类复用既有 3D 轮廓。——判定层同层直读、_draw 自绘现成、颜色即参数、改一行秒级验证；3D 观感后置 M2，双轨开关互不影响。
> 状态：规划待批准。执行者：实施窗口（插队批次，建议波3 验收前完成——否则波3 的禁疗/印记类无法目验）。

### 1.3 汇总：本批要做的 UI 件 = **1 个通用组件 + 3 个专属小件 + 2 个小调整**

1. **通用状态图标条**（一次做全员复用：色块图标+层数/秒数角标，数据源=player 状态变化信号）
2. **盾弧面+耐久**（_draw 弧形，follow 跟随球员、static 画在落点）
3. **印记层数**（图标条组件的层数角标能力，mark_changed 信号消费）
4. **充能点**（技能图标旁 N/M）
5. 必中锁定线（复用瞄准通路，小改）
6. 球隐身半透明（2D 球代理一行 alpha）

## 二、组件规范（2.5D 简约版）

- **图标条**：24px 色块图标（底色=状态分类色，中央单字符/符号），右上角秒数、右下角层数；上限一排 8 个，超出折叠为 "+N"
- **配色临时表**（注释标明"待 ElementColorBank 统一"）：禁疗=紫 / 禁能=蓝灰 / 反伤=橙红 / 免疫=白框 / 弱点=暗红 / 分摊=青 / 印记=绿 / 盾=金 / 治疗=翠绿
- **数据源协议**：UI 只读——消费各原语已交付的信号与查询接口（shield_state_changed / mark_changed / 状态灯查询），UI 层零判定逻辑（铁律）
- **刷新**：事件驱动重绘（不轮询），与 `_draw` 节点范式一致
