# 05 · V1-2 护盾原语计划（player_shield_obstacle 体外实体盾）

> 依据：技能规划/02 §1.4 工单流程 + §1.7 路线总纲。前置：V1-1 地基已完成（P2-1，已验收）。
> **语义澄清（2026-09-21 主人定）**：护盾 = **体外实体**——立在球员身前、跟随球员、挡球的物理盾墙；**不是**血条上先扣的数值层。机制雏形 = 现有岩石墙（field_obs_add：球撞障碍逐帧消耗攻击/球速，击穿继续飞），护盾 = 随身跟随版。
> 语义铁律：本工单只做判定层；盾体外观/碎裂特效/举盾动作 = 美术线消费接口。
> 状态：v2 修订待批准。执行者：实施窗口。
> 制定：2026-09-21（v1 数值盾方案作废）。

---

## 一、三问拆解（v2 修订）

| 问 | 答 | 落点 |
|---|---|---|
| Q1 作用对象 | **场地路线③（障碍实体）+ 球员绑定（随身跟随）** | ObstacleManager 体系扩展，非 player 数值管道 |
| Q2 生效时机 | T1 释放瞬间生成盾体 | handler 常规触发 |
| Q3 持续时间 | 存在 duration 秒 或 耐久被打光（先到为准） | 障碍生命周期（复用岩石墙模型） |

**与岩石墙（field_obs_add）的关系**：同一障碍基类的两个变体——
| | 岩石墙（已有） | 护盾（本工单） |
|---|---|---|
| 放置 | 鼠标点场地，固定不动 | 贴身生成，**跟随球员位置+朝向** |
| 归属 | 场地公共障碍 | 释放者个人（身边前） |
| 挡什么 | 挡所有球 | 挡球（友方球是否穿透=设计题 D3） |
| 消耗 | 球撞逐帧耗攻击/球速，可被击穿 | 同机制 + 盾自身耐久（被打 N 次碎） |

**解锁技能**（官方用例）：坚果盾（+加厚形态）、钻石壁垒、甲虫结壳（红/蓝）、忍术·水盾、防御盾/双重防御盾、光明护盾、风暴音盾、元灵结界（后深渊，高耐久档）≈ 10 技；V1-4 主角队用例 = 金刚系身前盾 1 技。
**不归本原语**（防混淆）：爱心守护/以柔制刚（软减伤来球，数值域，另行小标签）；元素免疫盾面（原语#16 V2 叠加）。

## 二、实现目标

```
handler 标签执行                        盾障碍实体（跟随节点）                  球碰撞
_apply_player_shield_obstacle          spawn：挂在释放者身边前                 球撞盾：
  params: hp/duration/width/height  →  每帧同步位置+朝向（脚下阴影/贴地）   →  逐帧消耗球攻击/球速
  （跟随模式：v1 跟释放者）              耐久 hp：球撞按既有障碍规则消耗         （岩石墙同款规则）
                                       hp≤0 或 duration 到期 → 碎/消          盾 hp 对应扣减
                                       emit shield_state_changed(hp)         球权结算走既有障碍交互规则
```

**对外接口（判定层交付物，表现层消费）**：
- 盾节点 `get_shield_hp() -> float`（只读）
- `signal shield_state_changed(hp, reason)`（reason: hit_hit/broken/expired——表现层据此播碎裂/消散）
- ObstacleManager 查询：`get_player_shield(caster_id)`（AI/球侧判断"该球员有盾"）

## 四、测试断言清单（≥10 项）

1. follow 模式跟随：盾位置 = 释放者身前（移动后仍跟随、朝向随转）
2. static 模式固定：盾生成后不随释放者移动/转向（与岩石墙行为一致）
3. 挡球消耗：球撞盾 → 球攻击/球速按岩石墙同款规则衰减
4. uses 次数制：撞 N 次盾碎（每次扣 1）
5. hp 数值制：按球攻击力扣盾耐久，耗尽盾碎
6. 超时消失：duration 到盾在也销毁（含信号 reason=expired）
7. 信号契约：hp 变化/碎/超时，`shield_state_changed` 值与 reason 正确
8. 击穿规则：威力高于消耗速率的球按岩石墙既有规则击穿（不因盾存在而行为漂移）
9. 索敌兼容：盾不是球员——AOE/索敓名册不含盾实体（权威名册口径，P0-2 后沿用）
10. 生命周期：释放者被淘汰/回合结束 → 盾随之清理（副系统生命周期规范）

## 八、设计决策（2026-09-21 主人拍板，已冻结）

- **D1/D2 跟随与朝向 = 按盾类型参数决定**：params 增加 `follow_mode`——`follow`（随身盾：跟随释放者位置+朝向转，如坚果盾/钻石壁垒）/ `static`（障碍盾：落地固定不动不转向，如放地上的盾墙型技能）。static 模式与现有岩石墙行为完全一致，follow 模式 = 岩石墙 + 每帧位置朝向同步
- **D3 挡球规则 = 所有物理盾都挡球**：不区分敌我，无队伍过滤（与岩石墙行为一致冻结；原作"只挡敌方"语义不做）
- **D4 耐久口径 = 双模式并存**：params 增加 `durability_mode`——`uses`（次数制：盾 = 可挡 N 次，每次撞击扣 1）/ `hp`（数值制：盾有耐久总量，按球的攻击力消耗，参照岩石墙逐帧消耗口径折算）。由技能参数选择，两套结算都实现
- 保留提醒：不做"碎盾反伤"（#5 反伤原语的事）、不做元素免疫盾面（#16 V2 的事），不提前耦合
