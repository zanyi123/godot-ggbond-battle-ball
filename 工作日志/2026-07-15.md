### 5. AnimationLibrary 共享引用导致动画错乱修复（核心）

**文件**：`scripts/test/player_3d_test.gd` ~ 行385-391, 501-517

**根因**：Godot 的 AnimationLibrary/Animation 是 Resource（引用语义），`load()` 返回缓存的 PackedScene，多次 `instantiate()` 的 AnimationPlayer 共享同一份 AnimationLibrary。第一次 `_rename_default_anim_to` 修改了共享资源，第二个 proxy 的 idle 动画被 catch 覆盖（idle length 从 10.0 变成 1.27）

**改动**：新增 `_deep_copy_anim_library()` 方法，在重命名前深拷贝所有动画库，断开与 PackedScene 缓存的共享引用；`_rename_default_anim_to` 中也用 `duplicate(true)` 拷贝动画数据

## 踩坑记录

1. **Godot 3→4 keycode 值完全不同**：Godot 3 的 KEY_F1=16777248，Godot 4.6 的 KEY_F1=4194332。用数字硬编码会静默失败（按 F1 触发 F5），必须用常量名。
2. **AnimationLibrary 是共享 Resource**：`load()` 缓存的 PackedScene 多次 `instantiate()` 后 AnimationPlayer 共享同一份动画库，修改第一个实例会影响第二个。必须 `duplicate(true)` 深拷贝后才能安全修改。
3. **_physics_process 提前 return 吞掉快捷键**：把轮询逻辑放在 controlled_player 检查之后，会导致 controlled_player 为 null 时快捷键永远不执行。轮询逻辑必须放在检查之前。
4. **TSCN 不支持内联构造**：`PlaneMesh.new()` 是 GDScript 写法，TSCN 中必须用 SubResource 引用。
5. **Blender MirrorModifier 无 vertex_group 属性**：Blender 的镜像修改器不支持顶点组限制，改用 `bpy.ops.mesh.symmetrize()` 只对称化选中顶点。
