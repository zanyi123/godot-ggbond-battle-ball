### 修复 2: 球飞行旋转 + 碰撞体（BallController.cs）

**问题**：迁移只搬了 GD 2D `ball.gd` 的位置搬运（`transform.position += flightDir * step`），漏了 `ball_proxy_3d.gd` 的 3D 旋转代理，且球无 Collider/Rigidbody。

**修复**：
- 加 `spinSpeed = 12f`（对应 GD `BALL_SPIN_SPEED=12.0`）
- 加 `ballMesh` 字段（球模型子节点）

- `Awake()` 自动补 `SphereCollider(isTrigger=true, radius=0.3)` + `Kinematic Rigidbody`

**对应 GD**：`ball_proxy_3d.gd` L18 `BALL_SPIN_SPEED=12.0`、L160 `ball_mesh_instance.rotate(Vector3.UP, ...)`

### 修复 3: 球权分配 + 主控球员重绑（RuntimeAutoBootstrap.cs + BattleManager.cs）

**问题**：`RuntimeAutoBootstrap.Awake`（`[DefaultExecutionOrder(-100)]`）早于 `BattleManager.Awake`，导致 `bm.ballNode` 未设置 → `Kickoff` 时球权不分配 → 球员无球 → 发球按键全失效。

**修复**：
- `BattleManager` 暴露 `public void AssignInitialBall()`
- `RuntimeAutoBootstrap.Update()` 每帧调 `_EnsureBallAssigned()`：比赛进行中且球无主人时自动分配
- `Update()` 加主控球员安全网：`controlledPlayer==null` 时重绑 `team_a[0]`

### 修复 4: 球模型不可见（BallController.cs）

**问题**：场景中 battleball 对象只有 BallController+SphereCollider+Rigidbody，**没有 MeshFilter/MeshRenderer**，球模型 `battleball.fbx` 从未挂到场景对象上。

**修复**：`Awake()` 检测无 `MeshRenderer` 时动态创建球体子对象：
```csharp
var meshObj = new GameObject("BallMesh");
meshObj.transform.SetParent(transform, false);
meshObj.transform.localScale = Vector3.one * 0.3f;
var mf = meshObj.AddComponent<MeshFilter>();
mf.sharedMesh = Resources.GetBuiltinResource<Mesh>("Sphere.fbx");
var mshR = meshObj.AddComponent<MeshRenderer>();
var mat = new Material(Shader.Find("Standard"));
mat.color = new Color(1f, 0.45f, 0.1f); // 橙红色
mshR.sharedMaterial = mat;
ballMesh = meshObj.transform;
```

## 踩坑记录

1. **执行顺序导致球权不分配**：`RuntimeAutoBootstrap` 标了 `[DefaultExecutionOrder(-100)]`，其 `Awake` 在 `BattleManager.Awake` 之前跑，此时 `BattleManager.Instance` 为 null，`bm.ballNode` 没被设置。`BattleManager.Start` 里虽有 `_AutoBindPlayers` 兜底找 `"battleball"`，但如果名称不匹配就分配失败。**教训**：跨脚本依赖用 `Update` 安全网兜底，不要只靠 `Awake/Start` 时序。

2. **球模型根本没挂到场景**：场景 battleball 对象只有逻辑组件（BallController/Collider/Rigidbody），没有视觉 Mesh。迁移时只搬了脚本没搬模型实例化。**教训**：场景对象必须同时有逻辑组件 + 视觉组件，Awake 里动态创建兜底。

3. **GD 有两套发球逻辑**：正式赛 `input_manager.gd`（蓄力）和测试场景 `field_tag_test.gd`（瞬发）。迁移时默认选了蓄力，主人测的是瞬发。**教训**：迁移输入系统时要确认测试入口对应的是哪套逻辑。

### 3. 决竞球规则落实（核心纠正）
**学习GD原码后纠正认知：决竞球没有球门！**

得分方式（2种）：
- **击倒得分**: 球击中对方球员→扣stamina→stamina<=0→被击败→攻击方得分
- **违规失分**: 球员越界(蓝色禁区/越中线/越内外场边界)→对手得分

修改：
- **BallController.cs**: 移除 `goalZHalf` 字段和 `OnGoalScored` 事件，`_CheckBoundaries` 移除球门得分逻辑
- **BallController.cs**: 场地常量全部×2（fieldX: ±6.5→±13, fieldZ: ±3.9→±7.8, outFieldX: ±8.5→±17）
- **PlayerController.cs**: clampX/Z 边界×2
- **BattleManager.cs**: 
  - 加场地常量（innerX: ±7.6, outerX: ±10.2, 中线x=0）
  - `Update()` 每帧检测3类违规：蓝色禁区(1)/越中线(2)/越内外场边界(3)
  - `_HandleViolation()`: 对手得分 + 传送违规球员到己方外场
  - `_OnPlayerDefeated()`: 监听球员 defeated 事件，攻击方得分 + 传送外场
  - 移除 `OnGoal()`，改为 `AddScore()` 兼容接口
- **TestBattle.unity**: battleball 节点 BallController 序列化字段更新（移除goalZHalf，边界×2）
