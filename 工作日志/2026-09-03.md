## 踩坑记录

1. **CS0104 二义性引用 PlayerSaveManager**：Core 真持久化版和 Systems UI 适配版同名类。解决：UI 层统一加 `using PlayerSaveManager = BattleBall.Systems.PlayerSaveManager;` 别名（4 个 UI 文件都加）。

2. **CS7036 没有与 XXXX 匹配的重载**：Godot GDScript 是动态弱类型（多参/少参/不传默认都行）→ C# 强签名。解决：TrainingManager/NutritionManager/InventoryManager 全部方法**铺齐 0/1/2/3 参所有重载**，少参内部传默认值调完整版本。

3. **CS0122 保护级别无法访问 / CS0117 不含某定义（PlayerController 大量 Spirit 兼容方法缺失）**：原 GD 代码链路里 AI/标签/UI 会调 PlayerController 的 12+ 方法（TurnOnLight/AddTickEffect/LoseStamina 等）。解决：PlayerController 里整段加兼容方法（既有 Pascal 属性能让 C# 读，也保留 snake_case 方法名给链路反射调用成功）。

4. **RewardSystem UI 类名直接调用报错**：原 GD 是 autoload 单例（全局 `RewardSystem.xxx()`），C# 方法是实例 virtual。解决：**不改原 virtual 签名**（避免影响继承/多态）→ 在 RewardSystem 里新增 3 个 `static` 包装方法内部转 `Instance` → UI 代码无需大改照样 `RewardSystem.RewardEnabledStatic()`。

5. **最后 2 个错误类型冲突报 CS1503/CS0029 怎么改都炸 → 试错 3/3 兜底**：BaseSystem（角色解锁列表）/ MatchResultUI（嵌套Dict装备对比）是最后卡 2 错的根因，数据链路还没通，先写死空 List / 空 Dict 保证**编译 0 errors**，把功能修的工作流移动到 Play 测后，避免试错超过 3 次。严格遵守 bug-fix 纪律：每轮只改一个根因。

6. **Git push 到 GitHub 超时（fatal: unable to access 443 connect timeout）**：国内网络 GitHub HTTPS 443 抽风。解决：PowerShell 遍历常见代理端口 7890/7897/10809/8080...，7890 ✅ 通。`git config --global http.proxy 127.0.0.1:7890` 配置全局代理 → 重推成功。

7. **GitHub GH001 大文件警告**：12 个动画 FBX 56~59MB、决竞球 GLB 84MB。解决：暂时忽略（仅警告，push 完全成功）；后续统一启用 Git LFS 跟踪 `*.fbx,*.glb,*.png,*.tga`。

8. **Unity 目前没有保存 MainMenu.unity 场景**：UI 场景只有 TestBattle / TestPlayer 两个。解决：P0 测主菜单/准备UI 时，用**空场景挂 UI 脚本**的方法（新建 GameObject → AddComponent → MainMenu.cs / PreparationUI.cs），因为 UI 脚本都是代码动态搭面板，不需要拖 UGUI 预制件。
