# 04 · 工单细化与开发系统对接（操1/操2/操3 逐大点落实）

> 定位：03 框架的落实细则——每个工单按大点拆到"改哪个文件、用哪个系统、怎么对接"，实施窗口照此作业，无需自行设计。
> 核心思路：**操作维度不造新系统，只在四个既有系统上开路由**——input_manager（输入分发）、skill_state_manager（技能状态机）、event_bus（事件）、skills.json schema（数据）；UI 层经 14 保存链落盘。
> 制定：2026-09-24。前置：14 保存链路合入。

## 二、操1 细化（四大块 × 12 类）

### 大点1：schema 字段（数据层）
- skills.json 条目允许 `"operator": "OP_XXX"`；DataManager 透传（零代码，JSON 任意字段自然带过）
- registry 说明文件补 operator 枚举表（12 类名+一句话交互描述）
- **校验规则**（随 14 保存链的校验器）：operator ∈ 12 枚举；passive 技能只允许 OP_AUTO；OP_MIDFLY/OP_TOGGLE 需对应 params

### 大点2：状态机扩展（skill_state_manager）
现状四态：IDLE → ACTIVATED → RELEASING → COOLDOWN。
扩展：ACTIVATED 后按 operator 进入**子态**，子态内左键/再按=推进：

```
ACTIVATED ──按 operator 分──→
  OP_AIM    → AIMING 子态   （鼠移=预览跟随；左键=确认释放）
  OP_POINT  → SELECTING 子态（鼠移=候选高亮；左键=锁定生效）
  OP_MARK   → MARKING 子态  （鼠移=候选高亮；左键=标记+自动追击）
  OP_MIDFLY → 无子态（投出后飞行中再按同键触发，次数受限）
  OP_TOGGLE → TOGGLED 子态  （再按=切换/关闭）
  OP_STEER  → STEERING 子态（投出后鼠移=实时引导，至结束条件）
  OP_AUTO/PLACE/KEY_JUMP/SUMMON/FP → 既有路径不变
任意子态：C 键 / 再按取消 → 回 IDLE（沿用既有取消语义）
```

### 大点3：输入路由器（input_manager）
- 新增"操作上下文"概念：当前激活技能的 operator 决定鼠标/键盘事件流向
- 事件映射表（路由器内部 switch）：

| 子态 | 鼠移 | 左键 | 再按技能键 | C |
|---|---|---|---|---|
| AIMING | 更新预览方向 | 确认释放 | — | 取消 |
| SELECTING | 更新高亮候选 | 锁定生效 | — | 取消 |
| MARKING | 更新高亮候选 | 标记+追击 | — | 取消 |
| STEERING | 实时引导飞行 | —（引导即操作） | — | 结束操控 |
| TOGGLED | — | — | 切换/关闭 | 关闭 |
| 无激活（MIDFLY 飞行中） | — | — | 触发干预（次数受限） | — |

### 大点4：逐类对接细则

| 类 | 对接细节 |
|---|---|
| OP_AIM | 预览显示：player 下挂简约虚线预览节点（功能性显示）；左键→把方向写给技能释放（球沿方向飞） |
| OP_POINT | 候选高亮：复用球员既有选中/高亮机制；坐标点（如白洞）用地面标记；左键→目标写入 target_data |
| OP_STEER | 核实 #17 `manual_steer` 方向源：若现为键盘朝向 → 改注入鼠标位置方向；操控态与 STEERING 子态同步（结束条件：命中/耗尽/超时/C） |
| OP_MIDFLY | 再按同技能键 → 查 ball 在飞 → 调 `recall_ball`（params.mode=recall）或 `boost_in_flight`（mode=boost）；次数=params.max_times，耗尽按键无效 |
| OP_TOGGLE | 再按 → 调波5 toggle 切换（形态参数组轮换/开关）；TOGGLED 态持续耗能沿用 #13 实现 |
| OP_KEY_JUMP | event_bus 加 `Action.JUMPED`；player.gd 跳跃处 emit；operator=KEY_JUMP 的技能订阅 → 触发（作用于召唤体/自身） |
| OP_MARK | 左键锁定目标 → 写入追踪目标（#22 追踪管道既有 target 字段）→ 球/召唤体自动追击 |
| OP_FP | **只核验不新写**：E 进 FP → 左键释放通路（预期已通，缺则按既有 FP 代码补路由） |
| OP_SUMMON v1 | 召唤体注册进可点选列表 → 左键地面=指定移动位置（v1 不做攻击指令，深化随 S5） |

### 大点5：反馈显示双轨（2026-09-24 主人纠偏后修正）

> 裁定：操作交互反馈（预览路径/落点圈/高亮/标记）是**世界空间**内容——玩家默认 3D 模式，2D 层画的看不见。载体分两类：
> - **屏幕空间 HUD**（状态图标条/层数/充能点）→ 2D（不变）
> - **世界空间交互反馈**（本批）→ **跟随显示模式双轨：3D 主 / 2D 兜底**

| 反馈件 | 3D 实现（主） | 2D 兜底 |
|---|---|---|
| AIM 预览路径 | 分段虚线小 mesh 沿方向铺地（unshaded） | _draw 虚线 |
| 落点/区域圈 | 环形 mesh 贴地 | _draw 圈 |
| POINT/MARK 高亮 | SkillOutline3D 挂目标 | 2D 轮廓 |
| STEER 引导 | 短线段串 | _draw 线 |
落点：3D 侧=skill_fx_3d_adapter 扩展（既有轮廓分发骨架）+2D 侧=skill_visual_manager 扩展；经 battle3d bridge 单向同步铁律。

### 大点6：测试（操1 断言清单 ≥14 项）
1. schema：operator 缺省=AUTO；非法枚举被校验拦截
2. 每新类 1 条路由断言（模拟输入序列→子态进入→确认→生效），共 AIM/POINT/MARK/TOGGLE/KEY_JUMP/MIDFLY 六条
3. STEER：鼠标方向注入断言（方向=鼠标位置向量）
4. MIDFLY：次数耗尽断言
5. TOGGLE：开→切→关循环断言
6. C 键：任意子态取消回 IDLE
7. 清洁断言：skills.json 无测试残留
