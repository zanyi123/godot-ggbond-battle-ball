## 二、工单卡

### 操1：operator schema + 输入路由核心

**范围**（12 类；AUTO/PLACE 既有不动）：
| 类 | 实现内容 |
|---|---|
| OP_AIM | 激活→方向预览路径自动跟随→左键单击确定释放 |
| OP_POINT | 激活→选点/选人态（候选自动高亮）→左键单击生效 |
| OP_STEER 补通路 | 释放后进入操控态，鼠标实时引导（核实 #17 既有注入是否即鼠标指向，缺则补） |
| OP_MIDFLY | 飞行中再按同技能键触发干预（效果由标签参数化：拉回/推进）——绑定 #14 接口 |
| OP_TOGGLE | 激活态再按=切换形态/关闭（与 #13 维持型共用按键语义，对齐波5 实现） |
| OP_KEY_JUMP | 跳跃动作入事件总线（新枚举）→ 技能订阅触发 |
| OP_MARK | 激活→标记态→左键点目标→标记+自动追击（联动 #22 追踪） |
| OP_FP 确认 | FP 态（E）准星跟随→左键释放通路核验（缺则补） |
| OP_SUMMON 基础版 | 召唤体点击指定位置（v1 点击式，深化随 S5） |
| OP_COMBO | 🔒 不实现（随 S1 方案）——schema 枚举保留 |

**schema**：skills.json 条目加 `"operator": "OP_AUTO"`（缺省，向后兼容）；registry 同步说明。

**断言要点**：12 类各一条路由断言（模拟输入序列→状态机到位）；KEY_JUMP 事件链；MIDFLY 次数限制；TOGGLE 开关循环；清洁断言（skills.json 无残留测试条目）。

**验收**：断言全过 + 全量回归 + run_sim 1 场危险=0。

### 操2：元灵管理操作选择器

**范围**：技能表单（新建/编辑）加"操作方式"下拉（12 选项，缺省 AUTO）→ 经 14 保存链路落盘；列表页显示操作方式徽标。
**文件**：元灵管理 UI 脚本（spirit_ui.gd 及实施窗口对应表单文件）。
**断言**：选择器选择→保存→重载回显正确；非法组合（如 passive+OP_STEER）校验提示。
**验收**：headless 断言 + 主人 UI 目验。

### 操3：端到端联调验收（无新代码）

**流程**：主人在元灵管理配 3~5 个带操作方式的技能（建议：一个 AIM 类如大惊雷、一个 POINT 类如黑白旋涡、一个 STEER 类、一个 TOGGLE 类、一个 MIDFLY 类）→ 实机按 01 §六检验单逐条操作 → 逐格对照"系统应响应"。
**产出**：通过清单 + 问题清单（问题回操1/2 修复后复验）。

## 三、红线适配（08 §五 全程有效，本框架补充两条）

1. **R1 精确适用**：操1 允许改 skills.json 的 **schema 定义**（operator 字段支持）；**禁止写入任何真实技能条目**——测试用临时条目交付时清除（git diff 数据文件为空）。

3. R2~R5 照旧（禁超范围/禁乱序/禁静默糊弄）。
