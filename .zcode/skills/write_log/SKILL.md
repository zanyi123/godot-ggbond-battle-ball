# 工作日志规范化写作技能

## 技能说明
每次对话结束后，**必须写两个日志文件**：
1. **当日工作日志**（`工作日志/2026-XX-XX.md`）：详细记录完成内容、待办、下一步
2. **zcode同步记录**（`工作日志/zcode同步记录.md`）：给 pi（另一个AI）看的交接摘要，按日期追加小节

## 双日志规则（重要）

每次写日志，两个文件都要更新：
- 日常日志 = 给自己/主人看的完整记录（成果+待办+方向）
- zcode同步记录 = 给 pi 看的精简交接（干了啥 + 关键结论 + 涉及文件 + 卡点）

---

## 日志1：当日工作日志

**文件位置**：`工作日志/2026-XX-XX.md`

### 格式

```markdown
# 决竞球 Battle Ball - 工作日志

## Tips（置顶）
- 每次对话写入当日工作日志
- 记得更新前一天的任务状态

---

## 2026-XX-XX

### 今日完成
- [完成点1]
- [完成点2]

### 待完成任务
- [ ] [待办1]
- [ ] [待办2]

### 下一步方向
- [方向1]
- [方向2]

---
```

### 要求

#### 今日完成部分
- **简洁列表**：每行一个实现点
- **不写代码**：不贴代码块、不写详细实现步骤
- **不写几百行**：保持简洁，通常20-30行以内
- **聚焦成果**：只写完成了什么，不写过程细节

#### 待完成任务部分
- **简短列表**：列出未完成的任务
- **优先级排序**：重要的放前面
- **用方括号标记**：`[ ]` 表示未完成，`[x]` 表示已完成

#### 下一步方向部分
- **简短说明**：下次对话要做什么
- **明确方向**：具体、可执行
- **关联待办**：指向待完成任务

## 日志2：zcode同步记录

**文件位置**：`工作日志/zcode同步记录.md`

这是给 pi（另一个AI协作伙伴）看的交接文档。pi 下次被叫起时读这个文件就能跟上 zcode 的进度。

### 格式（按日期追加小节）

```markdown
## 2026-XX-XX

### HH:MM —— <一句话标题>
**我让 zcode 干的**：<一句话说明任务>
**zcode 的结论/改动**：<关键结论，2-3行>
**涉及文件**：<文件列表>
**报错/卡点(若有)**：<关键报错或未解决问题>

### HH:MM —— <另一个任务标题>
...
```

### 要求

#### 内容
- **精简**：每个任务小节 5-10 行，不贴大段代码
- **聚焦交接信息**：pi 需要知道"zcode 改了什么、改到什么程度、有什么坑"
- **关键代码片段可贴**：但只贴核心几行（如签名变更、关键逻辑），不贴整个函数
- **报错必记**：遇到的报错原文贴上，方便 pi 对齐
- **未解决问题标注**：用 ⚠ 或"待pi确认"标记

#### 写作要点
- 标题用一句话概括任务（如"菲菲压线修复尝试"）
- "我让zcode干的"= 主人的原始需求
- "zcode的结论/改动"= 实际做了什么、结果如何（成功/失败/部分完成）
- "涉及文件"= 改了哪些文件（路径）
- 如果一个会话做了多个独立任务，拆成多个小节

## 示例

### 日常日志正确示例（简洁明了）

## 2026-06-14

### 今日完成
- 发球速度差异化：球员个性化球速 + 标签系统叠加
- 7个球员添加 ball_speed 字段（370-480）
- player.gd 新增 get_base_ball_speed() 方法
- ball.gd launch() 读取球员基础速度

### 待完成任务
- [ ] 角色系统UI显示验证（7个属性条 + 滚动）
- [ ] 比赛中发球速度验证（菲菲480 vs 猪猪侠420）

### 下一步方向
- 测试角色系统UI滚动和显示
- 测试比赛中发球速度是否符合球员值

### zcode同步记录正确示例
```markdown
## 2026-06-19

### 23:00 —— 菲菲压发球线修复（未彻底解决）
**我让 zcode 干的**：修复菲菲又压发球线的问题，要求修到通
**zcode 的结论/改动**：尝试4个方案（阈值/clamp截断/超时退守/极简转DEFEND），模拟全绿但主人实测仍压线。根因是菲菲supporter追clamp后够不到的目标反复追。极简方案保留在ai_manager.gd:1605，但未彻底解决。
**涉及文件**：scripts/battle/ai_manager.gd
**报错/卡点(若有)**：⚠ 主人实测仍压线，留作下轮专题；v3超时退守引入编译错误(current_state跨函数作用域)导致AI全瘫，已回退

### 23:30 —— 技能轮廓UI失效排查
**我让 zcode 干的**：技能激活后轮廓不显示了（之前正常）
**zcode 的结论/改动**：信号链路代码完整，加了3处诊断日志等主人提供运行时日志定位断点
**涉及文件**：scripts/battle/battle_manager.gd, scripts/systems/spirit_system/skill_visual_manager.gd
**报错/卡点(若有)**：待主人开游戏按键提供[诊断技能]/[诊断轮廓]日志
```

## 注意事项

1. **两个日志都要写**：不能只写日常日志漏掉同步记录，反之亦然
2. **日常日志不写技术细节**：不贴代码块、不写算法步骤
3. **同步记录可贴关键代码**：但只贴核心几行（签名、关键逻辑），用于交接对齐
4. **更新前一天状态**：查看前一天日常日志，更新已完成任务
5. **保持简洁**：日常日志20-30行，同步记录每个任务5-10行
6. **聚焦成果**：只写完成了什么，不写怎么完成的（日常日志）

## 技巧

- 用动词开头：完成、修复、新增、重构、实现
- 用简短描述：如"新增发球速度差异化"而不是"发球速度差异化功能的完整实现"
- 分类整理：相关内容放在一起
- 标记状态：用✅或[x]表示已完成，[ ]表示未完成
- 同步记录用时间戳：HH:MM 便于追溯
